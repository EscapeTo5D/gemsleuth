## 1. 背景与目标

某游戏内含"宝石推理"谜题：从若干种备选宝石中**有放回**随机取 4 颗排成答案；谜面给出若干条猜测记录，每条记录附带两个计数：

- **蓝标**：位置和种类都正确的宝石数量；
- **金标**：种类正确但位置不正确的宝石数量。

玩家需据此推断出唯一的答案序列。2026-09-08 会话中已对一个真实谜题（6 色 4 槽、6 条记录）完成人工推理 + 程序穷举双重验证：**标准 Mastermind 多重集计数语义与该游戏行为一致**（含重复宝石按较少一侧计数），该谜题唯一解为「紫紫紫黄」。

本工具是一个 Rust 桌面伴侣程序，目标是：

1. **整卷求解**：把谜面全部记录一次性录入，直接算出答案（或列出候选 / 报告矛盾）；
2. **陪玩助手**：玩家每猜一次、游戏每反馈一次，实时缩小候选范围并推荐下一个最优猜测。

## 4. 核心设计

### 4.1 数据模型

```rust
pub struct Settings {
    pub colors: usize,   // 4..=8，默认 6
    pub slots: usize,    // 3..=6，默认 4
    pub repeats: bool,   // 默认 true
}

pub struct Record {
    pub guess: Vec<u8>,  // 长度 = slots，元素为 0..colors 的宝石索引
    pub exact: u8,       // 蓝标数
    pub partial: u8,     // 金标数
    pub enabled: bool,   // 禁用后不参与过滤（排查矛盾用）
}
```

宝石在核心层只是 `0..colors` 的索引；"红/蓝/紫/橙/黄/绿"等语义仅存在于 GUI 调色板层（§5.2）。判定语义与颜色无关，参数变化时核心逻辑不变。

### 4.2 反馈判定 `judge(guess, candidate) -> (exact, partial)`

标准 Mastermind 多重集计数（已验证与游戏一致）：

```
exact = Σ_i [guess[i] == candidate[i]]
overlap = Σ_色c min(count(guess, c), count(candidate, c))
partial = overlap − exact
```

复杂度 O(slots)。

### 4.3 求解 `solve(settings, records) -> SolveOutcome`

1. **枚举全空间**：`repeats=true` → `colors^slots` 个组合（默认 1296；上限 8⁶ = 262 144）；`repeats=false` → 全排列 P(colors, slots)，此时要求 `slots ≤ colors`。
2. **过滤**：仅保留使**所有 enabled 记录**满足 `judge(record.guess, cand) == (record.exact, record.partial)` 的候选。
3. **结果三分支**：

```rust
pub enum SolveOutcome {
    Unique(Vec<u8>),                              // 唯一答案
    Ambiguous { candidates: Vec<Vec<u8>>, recommendation: Vec<u8> }, // 多候选 + 消歧推荐
    Contradiction,                                // 记录自相矛盾（有录入错误）
}
```

性能：默认参数下 1296 候选 × 记录数的判定在微秒级；最大参数 8⁶ = 26 万候选也在毫秒级，**UI 同步计算即可，无需异步**。

### 4.4 推荐策略（陪玩助手 + 消歧）

Knuth minimax：遍历**全空间**（不只当前候选集）中每个可猜序列 g，对当前候选集按 `judge(g, cand)` 分桶，取"最坏桶大小"最小的 g；平手时优先选本身仍属候选集者。首次（无记录时）推荐即该策略的自然开局，不硬编码。

复杂度控制：全空间 ≤ 20 000（覆盖默认 6⁴=1296、8⁴=4096、6⁵=7776）时做全量 minimax（默认参数下微秒~毫秒级）；更大的空间（如 8⁶=262 144）对 guess 空间按**固定种子**随机采样 2048 个再 minimax，保证极端配置下也在秒级内，且结果可复现。

### 4.5 错误处理

| 情形 | 处理 |
|---|---|
| 候选为 0（Contradiction） | 结果区标红"记录矛盾"；用户可逐条禁用记录，禁用某条后候选恢复非空 → 该条即嫌疑记录，界面提示 |
| 修改 Settings | 弹确认框，确认后重置当前会话（清空记录） |
| 记录录入校验 | `exact + partial ≤ slots`；`exact ≤ slots`；不合法的计数不允许添加/保存 |
| repeats=false 且 slots > colors | 设置界面直接禁止该组合（灰掉/校验提示） |

## 5. GUI 设计

### 5.1 布局（窗口约 1000×700，可缩放，中文界面）

```
┌──────────────────────────────────────────────────┐
│ 设置: 颜色数[6▾] 槽位数[4▾] 允许重复[✓] [重置会话] │
├──────────────────────────────────────────────────┤
│ Tab: [ 整卷求解 | 陪玩助手 ]                       │
├──────────────────────────────────────────────────┤
│ 记录区（两 Tab 共享同一份 SessionState.records）:  │
│  ① [橙][蓝][紫][红]  蓝×1 金×0   [启用☑][删除]     │
│  ② [橙][蓝][紫][绿]  蓝×1 金×0   [启用☑][删除]     │
│  ＋新增行: 点击宝石图依次填入槽位 + 蓝标/金标数字    │
├──────────────────────────────────────────────────┤
│ 结果区:                                           │
│  整卷求解 Tab → [求解] 按钮：                      │
│    Unique      → 唯一答案以大号宝石图展示          │
│    Ambiguous   → 候选列表（>50 折叠为计数）+ 推荐   │
│    Contradiction → 红色矛盾提示                    │
│  陪玩助手 Tab → 实时刷新（无需按钮）：              │
│    剩余候选 N 个 ｜ 推荐下一猜: [紫][紫][紫][黄]     │
│    候选列表（可滚动）                              │
└──────────────────────────────────────────────────┘
```

两 Tab 本质是同一数据模型（`SessionState { settings, records }`）的两种视图：整卷求解强调"录完整卷后一次求解"，陪玩助手强调"逐条增长、实时过滤与推荐"。

### 5.2 素材接口约定（F8）

| 文件 | 含义 |
|---|---|
| `assets/gems/gem_0.png … gem_7.png` | 各颜色宝石图（索引见下） |
| `assets/icons/exact.png` | 蓝标（位置和种类都正确） |
| `assets/icons/partial.png` | 金标（种类对位置错） |
| `assets/icons/unknown.png` | 问号占位 |

- 默认颜色映射：`0红 1蓝 2紫 3橙 4黄 5绿 6青 7白`（与截图谜题备选顺序对齐前 6 色，6/7 备用扩展色）。
- 全部素材经 `include_bytes!` 编译期嵌入，**exe 保持单文件**；
- **同名替换素材文件后重新编译即生效**，不需要改任何代码；
- 素材未到位期间，以从用户截图自动裁切的低清图（宝石约 60px、显示 32–64px）作为**占位**，开发不被阻塞；用户后续提供高清素材（≥128px 优先）替换。

### 5.3 中文字体

egui 内置字体不含 CJK。方案：运行时加载系统字体（按序探测 `C:\Windows\Fonts\msyh.ttc`、`simhei.ttf` 等常见中文字体），加载失败时回退内置拉丁字体并在界面提示。不分发字体文件，规避许可问题。

## 6. 测试策略

核心层全部为 `#[cfg(test)]` 单元测试（`cargo test`，无 GUI 依赖）：

| 测试 | 内容 |
|---|---|
| `judge` 单测 | 含重复宝石用例（如 guess=黄黄紫蓝 vs candidate=紫紫紫黄 → (0,2)），覆盖多重集计数语义 |
| **金标准测试** | 2026-09-08 真实谜题的 6 条记录 → 必须解出 `Unique(紫紫紫黄)` 且唯一；此测试锁死判定语义，防止回归 |
| 矛盾用例 | 添加一条与其它记录冲突的记录 → `Contradiction`；禁用该条后恢复非空 |
| 排列模式冒烟 | `repeats=false` 下全空间数量与求解正确性 |
| minimax 行为测试 | 小空间（如 3 色 2 槽）上验证推荐能最快缩小候选 |

GUI 层手动验收：中文渲染、素材显示、Tab 切换、记录编辑、矛盾排查流程。

| 风险 | 对策 |

| 高清素材迟迟未提供 | 占位图方案（§5.2），功能不受阻 |
