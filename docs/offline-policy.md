# 默认规则离线策略

## 当前可切换策略

界面默认选择“平均次数最少”，也可切换“最坏次数更少”。切换保留记录、
清除旧分析结果并重新计算。平均策略已通过完整精确搜索证明最优。

| 模式 | 全部答案提交次数之和 | 等概率平均提交次数 | 最坏提交次数 |
| --- | --- | --- | --- |
| 平均次数最少 | 5625 | 4.340278 | 6 |
| 最坏次数更少 | 5801 | 4.476080 | 5 |

每套策略都独立模拟了全部 1296 种答案，核对每个节点的步数保证。
成绩包含最终猜中答案的一次提交，仅适用于从开局持续采用同一策略且反馈准确。
中途切换后，未覆盖的候选集合会明确提示使用原有实时分析；不会沿用开局保证。

平均策略的精确重建、证明与恢复命令见 `docs/exact-search.md`。
空缓存重跑耗时约 95.7 秒，总成本下界与上界都为 5625，详见 `docs/exact-search-result.json`。
这证明在六色四槽、允许重复、答案等可能、最终猜中也计一次的规则下，
不存在平均提交次数更低的策略。

启发式基线生成器：`cargo run --release --example build_strategies`，
默认写到 `target/heuristic-policy`，避免覆盖已经证明最优的策略。
最坏模式逐层最小化最大反馈分组，平手优先猜候选答案。
两套策略将每种可达局面的推荐和验证步数分别保存在
`assets/policy_average.txt` 和 `assets/policy_worst.txt`，编译时嵌入程序。

## 上一版基线（保留用于比较）

范围：6 种颜色、4 个位置、允许重复，共 1296 个答案。

本表复用现有推荐算法生成完整策略树，并非全局最优搜索的结果。
生成器比较当前算法所使用的猜测，递归遍历每种实际可达反馈。
每个节点保存完整候选集合、下一猜和这套后续策略的最坏提交次数。

生成命令：`cargo run --release --example build_policy`

生成结果：371 个多候选节点，本机生成耗时约 40.2 秒。

| 提交次数（包含猜中答案） | 答案数量 |
| --- | --- |
| 1 | 1 |
| 2 | 4 |
| 3 | 29 |
| 4 | 292 |
| 5 | 910 |
| 6 | 60 |

全部答案等可能时，平均 4.763889 次，最坏 6 次。
这不是减少轮数的最优性证明；主要收益是把这些可达局面的在线搜索替换为查表。

界面仅在候选集合与表中条目完全一致时采用表中建议。
修改或禁用记录、自选猜测导致未知集合时，自动使用原来的实时推荐。
已用完猜测轮数时仍遵循原有最终答案流程。

独立验证：`cargo test --release core::policy -- --nocapture`。
测试逐一模拟全部答案，从实际反馈重新筛选候选，确保每条路径都有推荐、
可以终止，并且每个节点宣传的步数保证均成立。生成器不读取策略表，支持重建。
