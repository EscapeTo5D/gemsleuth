# 平均次数精确搜索

## 已完成的证明

默认游戏的总成本最优值为 **5625**，平均 **5625 / 1296 = 4.340277778** 次提交。
导出的这套平均最优策略最坏需要 6 次。
空缓存重跑访问并缓存 1,793,042 个候选集合，耗时约 95.7 秒，
证明下界与可行上界都为 5625。结果见 `docs/exact-search-result.json`。
随后独立模拟全部答案，核对每个分支的步数保证及总成本。

已内置策略 `assets/policy_average.txt` 的 SHA-256：
`1D07F94E5BB49FAAAC31A04F9B43B22A91A4F5A06225E662C249A9C0716EBD40`。

以下说明计算模型与复现方式。

目标：在默认 6 色、4 槽、可重复、答案等可能的规则下，最小化总提交次数。
最终猜中也计一次。已有策略是可行上界，不能用作最优性证明。

实现计划：
1. 独立精确求解器，枚举所有合法猜测。只用有证明的下界、等价反馈划分、
   完整开局的颜色/位置对称性剪枝。熵仅用于搜索顺序。
2. 对每个候选集合缓存已证明下界、可行上界与猜测。取消只保存已完成的结论，
   未完成节点不标为精确。
3. 命令行离线运行，支持时间限额、进度输出和检查点恢复；不占用界面线程。
4. 从已有平均策略导入可行上界。每次运行导出目前最好的完整策略并独立模拟所有答案。
5. 用独立、不剪枝的微型穷举器交叉验证；测试中断、恢复、剪枝边界与策略完整性。

递推：F(C) = |C| + min_g sum(F(C_feedback))，全对反馈不再递归，F(单候选)=1。
不能缩小候选且不能命中的猜测不会改善答案，直接跳过。

对于四槽，每次提交最多产生 13 个非终局反馈分支，并最多直接解决一个答案。
理想情况下第 1 层可解决 1 个答案、第 2 层 13 个、第 3 层 169 个……
把答案优先放在浅层得到总提交次数下界。真实游戏只能更差，故可安全剪枝。
对具体猜测，再按实际反馈分区累加各子集下界，可得到更强的猜测下界。

证明完成的条件是全开局下界等于已独立验证策略的总成本。
达到运行时间上限只表示暂停，绝不能声明全局最优。

## 运行与恢复

```
cargo run --release --example optimize_average -- --seconds 60
```

默认输出在 `target/exact-search/`。再次执行相同命令会加载 `search.checkpoint`，
复用已经证明的下界和已有策略。`--seconds` 是本次搜索的时间预算；到期后保存结果。
检查点写入临时文件后再替换，校验和损坏、规则不匹配或格式非法时拒绝恢复。
检查点来自本程序的受信任本地计算，不是可接受任意外部输入的证明证书。

输出 `best-policy.txt` 是完整可行策略；`report.json` 包含总成本上下界、
平均次数、最坏次数、是否证明最优和缓存局面数。
每次导出都逐一模拟全部答案，使用公共判定函数重新筛选候选，
不使用搜索器的反馈矩阵、成本缓存或证明下界。

用给定策略作为上界、从空缓存重做证明：

```
cargo run --release --example optimize_average -- --seconds 120 --out target/exact-proof-fresh --fresh --seed assets/policy_average.txt
```

如果限时结束还没证明完成，后续移除 `--fresh` 恢复计算。
`--seed` 只提供可行上界；程序会重新计算其成本，不会信任输入文件的成绩或最优性。

## 正确性检查

`cargo test --release core::optimal` 对照独立的无剪枝穷举器，检查三色两槽的
所有 511 个非空候选子集，以及包含重复颜色的四槽局面。另行覆盖严格成本阈值、
中断不产生虚假证明、保存恢复和损坏检查点拒绝。

只在完整开局合并颜色重命名及位置交换后等价的猜测，因此四槽开局共五类：
AAAA、AAAB、AABB、AABC、ABCD。其他局面仍枚举全部合法猜测。
相同候选集合若产生完全相同的非终局子集划分（仅反馈标签不同），后续最优成本相同，
可以合并。两种等价剪枝都不会遗漏更优策略。

大局面还使用一层前瞻下界：枚举下一猜，把每个反馈子集的理想容量下界相加，
取所有猜法中最小的值。它仍是下界，不将启发式评估当作证明。
